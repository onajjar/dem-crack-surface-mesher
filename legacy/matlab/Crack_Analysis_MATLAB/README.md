# Crack-analysis MATLAB bundle review

Review date: 2026-07-23

This directory is a historical scientific reference. The active application
does not call MATLAB. Crack reconstruction, characterization, synthesis,
visualization, reporting, and regression tests are implemented in Python.

The supplied bundle is approximately 1.1 GiB because it contains large CSV,
FIG, PNG, MAT, and presentation artifacts. Those assets are retained locally
for provenance and possible future measured-surface validation; they are not
runtime dependencies and are not added to Git.

## Ambiguous or rejected formulas

- `Ral = 1/mean(|gradient|)` is not a standard autocorrelation length and has
  inconsistent dimensions; it is not reported by Python.
- Several tortuosity calculations derive pixel width with point count rather
  than interval count and mix matrix row/column symbols. Python uses the
  physical coordinate differences along every profile.
- Maximizing Hurst-fit R² over many q ranges without a minimum scale span can
  select a short, nonphysical regression. Python requires at least four points,
  reports scale span and R², and warns below half a decade.
- The legacy H formula `H = -slope/2 - 1` is specific to a radially averaged
  two-dimensional surface PSD with slope `-(2H+2)`. Python's one-dimensional
  profile PSD correctly uses `H = (-slope-1)/2`; the two conventions are not
  mixed.
- Gaussian smoothing parameters in exploratory scripts were not tied to
  physical length. Python reports normal smoothing in grid points and does not
  smooth by default.
- Missing, closed, and negative apertures are not silently discarded.

## Retention and cleanup

Scientifically useful `.m`, raw measurement, `.mat`, `.fig`, `.png`, `.pptx`,
and license files are retained. Exact duplicate utilities remain where external
context or licensing could matter. The two generated `__pycache__` directories
and four MATLAB `.asv` autosaves (`main1`, `Tailhan_crack`,
`calculateRoughnessAndTortuosity`, and `correctDEAPMatrices`) were removed after
this review because they contain only regenerated bytecode or editor autosaves.

No legacy file is imported by the current Python application. The only new
MATLAB file, `../validation_cases/characterization_reference.m`, is an
independent analytical validation helper. Its output is committed as
`docs/validation/matlab-characterization-reference.json`; Python regression
tests compare against that result, so MATLAB is not needed to run the tests.
